# Tanvee Goenka: portfolio

A static HTML/CSS site built 1:1 from `Portfolio from Figma.fig`. It has no build step and no framework: open `index.html` or put the folder on any static host.

```
index.html                  Home page (hand-written, semantic HTML)
case-studies/
  indian-bank.html          Legacy to Loyalty      (generated from Figma)
  sthir.html                Sthir                  (generated from Figma)
  fermio.html               Fermio                 (generated from Figma)
  lexafide.html             Lexafide               (generated from Lexafide from Figma.fig + a hand-written end)
assets/
  css/site.css              Tokens, header, footer, home page
  css/case-study.css        Shared rules for the case-study canvas and mobile layout
  css/pages/*.css           Per-case-study styles (generated)
  css/home.css              Home page only (the shared shell stays in site.css)
  js/main.js                Header behaviour, canvas/figure scaling, lazy videos
  js/home.js                Home page only: starts the hero puzzle, the "Copy" button for the email address
  js/hero-scene.js          Home hero: the 3D objects that take themselves apart (Three.js, see below)
  js/vendor/                Three.js r169 (three.module.min.js, RoomEnvironment.js, MIT licence)
  img/home/                 Home page photographs, cropped and resized (see below)
  img/  video/  icons/      Optimised assets exported from the Figma file
  img/og/                   Link-preview images (Open Graph), one per page
tools/figma-export/         Script that regenerates the case studies and assets
  fixes.js                  Corrections applied to every exported page (see "Editing")
```

## Run it locally

```bash
python3 -m http.server 8000
```

Then open http://localhost:8000. Opening `index.html` directly also works, but a local server matches how the site behaves once hosted.

## How the pages are built

**Home (`index.html`)** is written by hand with flexbox/grid, using the exact values from the Figma frame (fonts, sizes, colours, spacing). It includes the design's prototype behaviour:
- "View case study" buttons darken on hover.
- A "Skip to content" link appears on keyboard focus (it's part of the shared header, on every page).
- The nav links scroll to the case studies and to "How I work". Resume opens the Google Drive link from the file.

The home page has four parts: an introduction (the positioning line and a 3×3 jigsaw: the four case studies at the corners, linking to them, four disciplines between them, and Tanvee's portrait in the middle), the case studies (each card in its own project's palette, Lexafide first), "How I work" (three photographs, each tied to evidence in the case studies) and a closing contact section. Its photographs come from the originals in `Desktop/Portfolio`, cropped so Tanvee is the only clear subject and exported as WebP at two or three widths for `srcset` (`assets/img/home/`). The hero line is "Hi, I’m Tanvee, a Strategy & Product Designer who loves finding the piece that makes it click", with the role and "click" as highlight chips and one small line underneath (Currently at Lexafide · Final year, FLAME University), for a Hero brand archetype with a touch of Lover: chaos to clarity. On load the puzzle pieces fly in from scattered positions and lock together, Tanvee's piece last with one pulse, then the two highlighted phrases draw in (about 2 seconds, once; "Shuffle the pieces" replays it). With reduced motion or without JavaScript the puzzle is shown complete. The puzzle SVG is generated by a small script (each piece is a path with tabs and blanks clipped around an image); to change a piece, edit the markup in `index.html` directly.

It also reflows on tablets and phones. The Figma file only has the 1440px desktop design, so the small-screen layout is my adaptation.

**Case studies** are free-form Figma canvases with hundreds of absolutely placed layers, so they are exported by `tools/figma-export/build.js` instead of being hand-coded. The exporter:
- positions every layer exactly as in Figma
- lays text out line by line using Figma's own line breaks. Across the three pages, about 98% of text baselines land within 1.5px of the design.
- expands components, masks, tables, connectors and the two videos
- exports images as resized WebP files (the Figma file holds 282 MB of images; the site uses 5.3 MB)

`main.js` scales each 1440px canvas to the width of the browser window, so a case study looks the same at 1280px as at 1920px.

**Case studies on phones and tablets (1023px and below)** get a separate layout generated by `tools/figma-export/mobile.js`. The Figma file only has desktop frames, so this layout is my own design, built from the same layers:
- Text is re-set at mobile sizes and flows into a single column. Bullet lists become real lists.
- Photos and videos go full width. Captions stay under their picture.
- Cards keep their colours, corners and borders. Rows of chips wrap, and sets of cards, swatches or phone screens become 2- or 3-column grids.
- Diagrams (journey maps, mind maps, stakeholder maps, overlapping collages) keep their Figma layout. If they're still readable at the column width they're scaled to fit; if not, they become a strip you swipe sideways.
- Full-width coloured bands become the backgrounds of mobile sections, so each page keeps its colour rhythm.

When the automatic choice for a section is wrong, set a treatment for that layer in `MOBILE_OVERRIDES` at the top of `build.js` (`figure`, `scroll`, `scroll-center`, `flow`, `solo`, `descend` or `skip`), then re-run the exporter. Loose layers that belong together but aren't in a shared frame, like the Sthir form-experimentation collage, can be listed under `groups` and shown as one figure or as a row. The shared header and footer come from `tools/figma-export/partials.js` and are written into every page, including `index.html`.

## Editing

- **Home page:** edit `index.html` and `assets/css/site.css` directly.
- **Header/footer links (resume, email, LinkedIn):** edit `tools/figma-export/partials.js`, then re-run the exporter. It rewrites the marked header and footer regions in `index.html` too.
- **Corrections that aren't in Figma yet** (copy errors, a stray component, contradictory labels, alt text, heading levels, a few mobile layouts): `tools/figma-export/fixes.js`. `build.js` applies them to every page it writes, so they survive a re-export. To apply them to the pages already in `case-studies/` without re-exporting, run `node fixes.js` in `tools/figma-export` (it's safe to run twice). When a fix is also made in the Figma file, delete its entry.
- **Case studies:** change the design in Figma, export the file again (File → Save local copy), replace `Portfolio from Figma.fig`, then run:

  ```bash
  cd tools/figma-export
  npm install
  node build.js
  ```

  The exporter needs Node 18+, ImageMagick (`magick`) and `ffmpeg`. On macOS: `brew install imagemagick ffmpeg`. Images and videos that already exist are skipped. Delete `assets/img` or `assets/video` to force a fresh export.

- **Lexafide case study:** exported from its own file, `Lexafide from Figma.fig` (put it in the repo root), with `node build.js --only=lexafide`. The Figma canvas stops where the Comms Log chapter ends (`until` in `PAGES`); everything after it (from "The Figma file wasn't the finish line" to Outcomes) is hand-written in `tools/figma-export/lexafide-tail.html`, styled by `assets/css/pages/lexafide-tail.css`, and appended by the exporter. Edit those two files for that part; edit the Figma file for the rest. If ImageMagick isn't installed, the exporter converts images with `sharp` when it can be required (`npm i sharp`, or point `NODE_PATH` at a folder that has it).

## Known differences from Figma

- **Image adjustments are not applied.** About 35 photos in the file use Figma's exposure, contrast or temperature sliders. The site shows the original photos.
- **Proprietary fonts are swapped.** The ad mock-ups inside the Fermio case study use Product Sans and SF Pro, which can't be served from the web. They fall back to similar fonts.
- **"Hover to view the personas"** (Indian Bank): on desktop the personas show their details on hover or keyboard focus (`main.js`). Phones have no hover, so the mobile layout lists the three persona summaries under the illustration instead (`fixes.js`).
- **The mobile and tablet case-study layouts** are generated, not taken from Figma, because the file has no mobile frames. Some dense diagrams scroll sideways on phones rather than shrinking to unreadable text.

## The 3D hero (`assets/js/hero-scene.js`)

Six sculptural objects (rocket, lightbulb, flower, star, trophy, puzzle cube) take themselves apart and reassemble on the other side of the hero text, in a 49-second loop. Before breaking apart, each one does its own thing: the rocket shakes and lifts off, the lightbulb switches on (a turquoise glow, light and halo), the flower twirls, the star spins, the trophy is raised, and the puzzle cube twists its top layer. Everything is real Three.js geometry; nothing is a video.

- **One component library, reused everywhere.** `GEOMETRY` holds the shapes (rounded cube, sphere, capsule, rounded cone, rounded cylinder, torus, curved wedge, rounded triangular prism). `PIECES` gives each piece one shape and one colour for good. `OBJECTS` lists where each piece sits in each object. A piece never changes shape: shared pieces fly from one object to the next; pieces an object doesn't need shrink away, and new ones grow in while the old object is still coming apart.
- **The text stays HTML.** The canvas sits behind the hero (`pointer-events: none`). `layout()` measures the welcome line and every rotating phrase, and keeps all objects and flight paths outside that area: on wide screens the objects sit either side and pieces travel above or below the text; on narrower screens both objects share the band under the text.
- **Interaction is a temporary push.** Pointer or touch near a piece offsets it (away, with a slight curl and the gesture's direction); the offset decays and the timeline never pauses. Horizontal swipes on the hero nudge pieces; vertical swipes scroll the page as normal.
- **Timing:** `HOLD`, `EXIT` (the signature move, the end of each hold), `TRANSITION`, `FLIGHT` and `STAGGER` at the top of the file. `SEQUENCE` sets the order and side of each object.
- **To change an object,** edit its entry in `OBJECTS`: each piece is `[x, y, z, rotX, rotY, rotZ]` in object space (about 2.4 units tall). `arrive` adds a settle-in motion (`dy` lift, `rz` turn, `open` for the flower's petals), `exit` sets the signature move before it breaks apart (`launch`, `shake`, `glow`, `twirl`, `spin`, `lift`, `rock`, `twist`), and `last` makes one piece arrive last and snap in. Where the objects sit under the text (narrow screens), upward moves are turned sideways or skipped so nothing reaches the text.
- **Fallbacks:** with `prefers-reduced-motion` the hero shows a still lightbulb and rocket; without WebGL it shows just the background and the text. Rendering stops when the hero is off screen or the tab is hidden.
